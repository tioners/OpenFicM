# OpenFicM 0.13.1

## Gemini 400 的补充加固

0.13.0 已经修掉了 Gemini 工具定义报 400 的根因（转换时把“参数名 → 定义”的映射本身当成了参数定义，导致每个工具的参数表里混进一个值为字符串的伪参数）。

这个版本再加两道保险，用于覆盖 0.13.0 之前遗留的环境和以后可能出现的来源：

- **请求前强制矫正**：组装 Gemini 请求时，对每个工具的参数定义做一次递归清洗。无论定义来自内置工具、插件，还是以后接入的远程工具，只要参数表里出现字符串等非对象值，就地改写成合法的 `{ "type": ... }`，不会让整次请求被拒绝。
- **错误提示能自我定位**：失败提示里新增一条专门识别 Gemini 工具定义格式错误的分支。以前它只会显示“供应商拒绝了本次请求（400）”，看不出是格式问题；现在会直接提示“0.13.0 起已修复，请在设置 → 高级确认当前版本号”，避免在旧版本上反复试。

## 如果你在 0.13.0 之前见过这个报错

原始报错形如：

```
Invalid value at 'tools[0].function_declarations[0].parameters.properties[0].value'
(type.googleapis.com/google.ai.generativelanguage.v1beta.Schema), "STRING"
```

这是 0.13.0 之前的转换缺陷造成的。升级到 0.13.1 即可；升级后如果仍出现 400，请展开“原始错误详情”把内容发出来，那会是另一类原因（例如模型名不被该接口支持、Key 权限不足、参数取值越界）。

## 验证

- 用“旧缺陷产物”（参数表里混入字符串、伪参数、两层嵌套数组）作为输入，清洗后所有参数值都是合法对象。
- 项目里全部 34 个真实工具走完整链路（转换 + 清洗），参数表中没有一处非对象值，嵌套数组结构保持正确。
- 类型检查通过。

## 兼容性

- 沿用 0.7.0 起的正式签名证书，可直接覆盖升级。
- applicationId `com.openfic.mobile`，versionCode 26，minSdk 28，仅 arm64-v8a。
- 只调整发往 Gemini 的工具定义与一处错误提示，不改数据库、不改其他供应商的请求格式。
