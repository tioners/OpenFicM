# OpenFicM 0.7.4

## 智能体协作与限流修复

本版针对"助手要么被 429 打断、要么提示本轮角色或世界书检查未全部完成"的问题，把移动端 Agent 的请求调度对齐上游 OpenFic 桌面端。

- 取消运行时强制委派。桌面端只在提示词里建议按专业分工调用子智能体，移动端此前把它做成了硬性要求：主智能体没有主动委派时，运行时会先追加一轮提醒请求，再自动补一次完整的子智能体循环，最后还要一轮整合。普通续写因此被放大成双倍请求。现在是否委派完全由模型按任务判断。
- 新增全任务模型请求预算。主智能体与其全部子智能体共享一次对话最多 24 次模型请求，超出后明确报错并提示拆分需求，不再出现单条消息把中转站每分钟请求配额打满的情况。
- 修正一致性检查的状态显示。此前无论是否真的核对过角色与世界书，界面都会写"已核对角色与世界书，并同步确认的变化"。现在只有实际调用过角色和世界书工具才这样显示，否则如实标注"未发现需要同步的角色或世界书变化"。
- 服务端过载类错误（500、502、503、504、408）由最多重试 3 次改为最多 2 次。429 仍然立即上报、不自动重试，界面保留手动重试入口。
- 移除已失效的协作分支：无法触达的"复杂任务未完成专业子智能体协作"报错、自动补委派的兜底选择逻辑，以及不再产生任何效果的子智能体一致性状态合并。

## 兼容性

- 沿用 0.7.0 起的正式签名证书，可直接覆盖升级。
- applicationId `com.openfic.mobile`，versionCode 11，minSdk 28，仅 arm64-v8a。
- 本地作品、章节、角色、世界书、会话和文风版本不受影响。
