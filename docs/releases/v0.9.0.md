# OpenFicM 0.9.0

## 改进：参考文风改成一份持续演进的文风文件

此前每蒸馏一轮都会新增一个版本文件。蒸到第五轮，《书名》参考文风就会以 V1、V2、V3、V4、V5 并列在文风书库里；而合并逻辑本来就是"在上一版基础上并入新证据"，也就是说只有最新一版有效，其余全是中间态。既看不出该用哪一份，也让选择、删除和跨作品复用变得啰嗦。

本版把参考文风改成**每本参考书一份**：继续蒸馏直接改写这一份，指南在多轮样本上持续变准，反复蒸馏得到的是同一份越来越完善的文风，而不是一堆版本。

- 蒸馏（首轮与继续蒸馏）和 Agent 的 `save_reference_style_profile` 都改为就地更新同一份参考文风。
- 升级后首次启动自动合并已有的多版本：保留最新指南、删除中间版本；作品原先选中的版本自动改指保留的那一份，不会静默退回"不使用文风"。
- 章节草稿记录的"当时用了哪份文风"一并改指保留的那一份，不会因为外键置空而丢失记录。
- 参考文风不再显示版本号——只剩一份时 V 号没有信息量；作者文风仍按版本累积，方便回看个人风格的演进。
- "重新开始"会用新结果替换现有参考文风，改为二次确认后再执行。
- 文风书库、助手、写作页的文风名称统一走同一处格式化逻辑，各页面显示一致。

## 兼容性

- 沿用 0.7.0 起的正式签名证书，可直接覆盖升级。
- applicationId `com.openfic.mobile`，versionCode 17，minSdk 28，仅 arm64-v8a。
- 合并只删除同一本书的中间版本，指南内容取最新一版，不会丢文本；作者文风版本完全不受影响。
- 蒸馏覆盖进度（第几轮、覆盖到第几章）沿用原有记录，升级后继续蒸馏仍从上次位置往后推进。
