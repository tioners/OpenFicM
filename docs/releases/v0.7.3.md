# OpenFicM 0.7.3

## 可靠性修复

- 1M 上下文模型不再需要把最大输出 Token 填成 1000000；历史超大配置会在请求层回退到安全默认值。
- 429 不再自动重复请求，避免助手、蒸馏和子智能体放大限流；失败后可使用界面中的重试。
- 助手只展示仍属于有效供应商的模型，并清理删除供应商后遗留的会话和默认模型引用。
- 子智能体或角色、世界书一致性检查失败时记录警告并继续返回主智能体结果，不再直接把整项任务判定为失败。
- 大章节、角色、世界书和文风指南工具结果增加边界，减少普通模型因上下文过大导致的任务未完成。

## 文风蒸馏

- 每批分析成功后保存本机断点，429、网络中断或汇总失败后再次点击会从已完成批次继续。
- 仍按最多 24 个章节样本、每 6 段一批、最多 4 次批次分析加 1 次汇总请求执行，不上传整本小说。
