# OpenFicM 0.12.0

## 助手回复支持 Markdown 渲染

此前助手消息就是一条纯文本，所以模型输出的 `**重点**`、`## 标题`、列表和代码块会带着标记原样显示，读起来很吵。本版把助手回复渲染成排版好的内容。

支持范围：

- 标题（一至六级，字号递减）、粗体、斜体、删除线。
- 有序与无序列表，支持嵌套；引用块带左侧强调条；分隔线。
- 行内代码与围栏代码块：代码块单独成块、等宽字体、显示语言名，超宽可横向滚动。
- 表格：保留原稿的左/中/右对齐，可横向滚动。
- 链接：可点击并交给系统浏览器打开。

安全与隐私上的取舍：

- 不解析 HTML。模型输出里的 `<script>`、`<img onerror=...>` 之类只会被当作文本，不会执行。
- 链接只放行 `http`、`https`、`mailto`；`javascript:`、`data:`、`vbscript:` 这类协议既不会生成可点链接，也不会被打开（解析库本身还会再挡一层）。
- **不加载远程图片**：遇到图片只显示 `[图片：说明]` 占位，避免对话内容触发外部网络请求。
- 用户自己发的消息仍按纯文本显示，不会因为输入了 `1. ` 就被擅自改成列表。

每条助手消息底部的“复制”拿到的仍是完整原文（含 Markdown 标记），需要原始文本时以复制结果为准。

## 实现要点

- 解析用 `markdown-it`（纯 JS，无原生模块，不增加需要 prebuild 的依赖），渲染层把 token 转成 React Native 组件，全部样式沿用现有主题色。
- 解析结果按消息内容缓存，流式输出刷新时不会重复重建整条消息。
- 解析异常时退回单段纯文本，不会让整条助手消息消失。

## 兼容性

- 沿用 0.7.0 起的正式签名证书，可直接覆盖升级。
- applicationId `com.openfic.mobile`，versionCode 23，minSdk 28，仅 arm64-v8a。
- 历史消息不需要迁移：渲染发生在显示层，数据库里的原文与 Markdown 标记都保持原样。
- 未改动模型请求、Agent 工具和文风逻辑。
