# OpenFicM 0.8.1

## 修复：开放笔记权限后 Agent 仍被拒绝调用笔记工具

0.8.0 加入笔记后，"设置 → 工具权限"里可以给读取笔记、创建笔记、编辑笔记、移动笔记、删除笔记单独授权，但授权之后助手调用这些工具依旧被拒，笔记功能对 Agent 等于不可用。

问题不在权限系统。移动端把内容包 `resources/openficm-agent-catalog.json` 里的 `toolNames` 当作唯一白名单：它既决定哪些工具声明给模型，也决定运行时允许执行哪些调用。而这份目录一直是 1a848fb 生成的版本，那时笔记功能还不存在，8 个内置智能体的 `toolNames` 里没有任何笔记工具。于是无论权限设成"允许"还是"每次询问"，工具都不在可用列表里——授权再细也没有作用。

- 生成脚本按后端的 `note_read` / `note_write` 工具类别补齐白名单：全部内置智能体可读笔记，build / composer / writer / actor 可写笔记，与桌面端 `DEFAULT_AGENT_DEFINITIONS` 的授权保持一致。
- 重新生成 Agent 目录并把固定提交升到补齐后的提交，首次安装和"一键拉取运行资源"都会拿到新目录。
- 生成目录时固定 LF 换行：移动端按下载文本校验 SHA-256，换行风格不应随开发机的 Git 设置变化。
- 同一个固定提交也提供 Lorn 移动端目录，该文件的校验值同步到仓库现有版本。

## 各智能体的笔记工具

| 智能体 | 笔记工具 |
| --- | --- |
| build、composer、writer、actor | 读取 + 写入 |
| plan、explore、auditor、reviewer | 仅读取 |

写入类笔记工具默认权限仍是"每次询问"，可在"设置 → 工具权限"改为"允许"。

## 兼容性

- 沿用 0.7.0 起的正式签名证书，可直接覆盖升级。
- applicationId `com.openfic.mobile`，versionCode 16，minSdk 28，仅打包 arm64-v8a。
- 已装旧 Agent 目录的设备会在启动资源检查里看到"部分运行资源尚未安装"，点"一键拉取并预热"重新下载目录即可；笔记、章节、角色、世界书等本地数据不受影响。
- 自定义智能体不受影响：它们的工具白名单本来就是全部工具。
