## 上下文管理（#7）

“设置 → 上下文”新增两组选项。默认值和旧版一致（按消息条数、丢弃较早消息），升级后不改设置就不会有任何变化。

### 限制方式：按消息条数 / 按 Token 数

- **按消息条数**（默认）：保留最近 N 条消息，和以前一样。
- **按 Token 数**：填写所用模型的上下文窗口，例如 128000。应用会先扣掉该模型的“最大输出 Token 数”，剩下的额度用来放系统提示词、工具定义和对话；对话从最新一条往前装，装不下的算作超出。

按 Token 数时需要知道的几点：

- Token 数是**估算**的：手机上没有各家模型的分词器，按“一个汉字约 1 个、三四个英文字符约 1 个”计算，并留 10% 余量。它不会和供应商账单上的数字完全一致。
- 上限是全局的一个值，不随模型切换。换用上下文窗口更小的模型时，需要把它调低。
- 一次任务里读取的章节等工具结果把请求撑到上限时，较早的读取结果会被强制清理，即使关闭了“自动清理较早的工具结果”。写入类结果不会清理，所以极端情况下请求仍可能超出，那时会看到供应商返回的超长报错。
- 可填范围是 4000 到 2000000，填写超出范围的值会提示错误并且不保存。

### 超出上限时：丢弃较早消息 / 生成摘要

- **丢弃较早消息**（默认）：超出的较早消息不再发给模型。聊天记录本身不会删除，仍然能在对话里看到。
- **生成摘要**：超出时用当前选中的模型把较早的一半对话压缩成一份摘要，保存在这个对话里，之后每次请求都带上。

生成摘要时需要知道的几点：

- 只有压缩的那一次会多发一个模型请求，之后对话再增长半个上限才会再压缩一次，不是每轮都多一次。压缩时运行记录里会出现一步“整理较早的对话”。
- 摘要由模型生成，可能漏掉细节。摘要里要求保留的是你的明确要求和禁忌、已经确定的设定与情节、已完成的操作和未完成的事项；章节正文、角色和世界书本来就存在作品里，助手需要时会重新读取。
- 摘要生成失败（限流、超时等）时，这一次自动按“丢弃”处理，任务照常继续，运行记录里会标出失败原因。
- 编辑了已经被摘要覆盖的较早消息后，旧摘要作废，下次超出时重新生成。
- 首次对一个很长的对话开启摘要时，只取离现在最近的约 2.4 万字符生成摘要，更早的部分不进入摘要。
- 摘要只作用于你和主智能体之间的对话；子智能体每次只拿到一条委派任务，没有历史可压缩。
