# OpenFicM 0.13.0

## 夜间模式

设置 → 通用里新增“夜间模式”，可选**跟随系统 / 浅色 / 深色**，立即生效、不需要重启，选择会被记住。

- 两套完整调色板，不只是把背景变黑：文字、次要文字、边框、主色、危险色、选中态底色、失败卡片、阴影都单独给了暗色值。
- 除了各页面的样式，导航容器、状态栏、底部标签栏也跟随配色，切页不会闪一下白底。
- 此前散落在各处的 8 种写死颜色（选中块、失败卡、按钮文字、阴影）统一收进调色板，暗色下不会出现白底绿框的割裂感。

## 断线后不再“忘记自己做过什么”

此前网络超时后点重试，助手会从头再来：已经写好的章节可能被重复创建，已经改过的设定可能被再改一遍。原因是工具调用记录只存在内存里，重试时只回放了你的原话。

现在：

- **执行前先落盘**：每个任务开始前先写一条“正在执行”的记录，工具状态变化时同步更新。即使 App 被系统杀掉，重启后仍能看到“哪些写操作已执行、哪些结果未知”，不会盲目重跑。
- **重试带上执行记录**：失败重试时，上一轮**已完成的写操作**会作为一条摘要交给助手，明确告知“这些已经做过，不要重复”。读取类操作不进摘要（重跑没有副作用）。
- **结果未知会提醒核对**：如果断连时某个写操作正在执行，会提示“可能已经写入，继续前请先核对”，而不是直接重做。
- **失败提示更清楚**：失败消息下方会显示“已保留 N 个已完成步骤……另有 M 个步骤未完成”，点重试前就知道会带回什么。
- 连续重试会累积记录，第二次失败不会把第一次的进度也丢掉。

## 修复：Gemini 官方 API 一律 400

接入 Gemini 官方接口时，所有请求都会被拒绝。原因是转成 Gemini 工具定义时，把“参数名 → 定义”这个映射本身也当成了参数定义，于是在每个工具的参数表里多塞了一个叫 `type` 的伪参数（值为字符串）。Gemini 要求参数表里每一项都必须是对象，因此直接 400。

- 修正转换逻辑，参数表本身不再被当作定义，也不再混入伪参数。
- 同时剔除 Gemini 不支持的 JSON Schema 关键字，空 `required` 不再发送，`enum` 统一为字符串数组，无参数工具不再发送空参数表。
- 已用项目里全部 34 个真实工具定义逐个校验：53 个参数节点全部合法，嵌套数组（如提问工具的 `questions[].options[]`）结构正确。
