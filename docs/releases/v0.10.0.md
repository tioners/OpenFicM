# OpenFicM 0.10.0

## 文风蒸馏改成后台任务

此前点“蒸馏文风”之后整个参考书窗口都被锁住：关闭按钮点了没反应、点遮罩也关不掉、按钮全部变灰，一轮 5 次模型请求跑完之前什么都做不了。蒸馏本来就是异步的，锁住界面只是实现方式的问题。

- 现在点开始即可关掉窗口、离开文风书库去写正文或翻别的作品，任务在后台继续。
- 文风书库顶部横幅显示“正在蒸馏《书名》”和实时进度，右侧可随时取消；跑完提示第几轮、覆盖到第几章，关掉即收起。
- 取消会立刻中断在途请求；已分析完的批次备忘录留在断点里，再点“继续蒸馏”会从断点接着跑，不重复已完成的批次。
- 同一时间只跑一个蒸馏任务，避免几个任务一起抢同一套限流额度。
- 说明：这是应用内后台。整个 App 被切到后台或被系统回收时，Android 不保证继续；回到应用后再点“继续蒸馏”即可接上。

## 模型与供应商

- **OpenAI 新旧接口可选**：OpenAI 兼容供应商现在可以在 Chat Completions（`/chat/completions`，兼容性最好）与 Responses（`/responses`，OpenAI 新接口）之间选择，按供应商保存；Gemini 与 Anthropic 仍各走自己的协议。中转站大多只实现旧接口，选错的典型表现是请求直接 404。
- **已有供应商可编辑**：显示名称、Base URL、接口都能改，API Key 留空表示保持原值——切换接口不再需要删掉供应商重建，也不会连带丢掉它下面的模型。
- **获取模型后一步入库**：模型列表里点一条就直接加进该供应商，窗口不关闭、可连续添加，已添加的标成“已添加”；参数取“添加模型”区域的温度与最大输出 Token，没填就用默认值。同一供应商下相同模型 ID 不会重复添加。
- **单个模型可删可改**：模型行右侧可以单独删除该模型（默认模型指向它时清空这个选择，供应商与其它模型不受影响），也可以单独调整它的名称、温度与最大输出 Token。

## 兼容性

- 沿用 0.7.0 起的正式签名证书，可直接覆盖升级。
- applicationId `com.openfic.mobile`，versionCode 18，minSdk 28，仅 arm64-v8a。
- 数据库新增 `providers.api_mode` 列，旧供应商默认按 Chat Completions 调用，行为与升级前一致。
- 已保存的供应商、模型、默认模型选择、参考文风与蒸馏覆盖进度都保持不变。
