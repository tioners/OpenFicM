# OpenFicM 0.14.0

这一版集中处理三件事：助手被 API 限流、思考型模型报 `reasoning_content` 的 400、以及助手与上游 OpenFic 的对齐。

> 这一版的请求层改动只在电脑上用模拟的模型服务验证过，**还没有在真机上跑过**。升级后如果助手请求异常，先到"设置 → 连接"关闭"流式接收回复"再试，并把原始错误详情发出来。

## 升级后请先做一件事

**已经添加过的模型，最大输出不会自动变**，仍是原来的数值（多数是 4096）。请到"设置 → 模型与供应商"把常用模型手动调到 8192 以上，否则写整章正文时仍然容易被截断。

## 助手被 API 限流

排查结论：不是并发太多（请求一直是一个接一个发的），而是三件事叠在一起——一次任务里的请求首尾相接没有间隔、每次请求都把之前读过的内容重新发一遍所以越来越大、一遇到限流就直接判任务失败。

- **遇到限流先等再试**。默认最多尝试 3 次，每次等 5 到 30 秒（供应商给了等待时间就按它的来）。额度或余额用完不会重试，因为等多久都不会恢复。次数可在"设置 → 连接"里调，填 1 就是旧行为。
- **自动清理较早的读取结果**。一次任务里读过的章节、角色等内容累计超过约 4 万字符后，较早的会换成一句占位说明，最近 4 条保留；写入结果、技能指令和子智能体结论不受影响，助手需要时会重新读取。"设置 → 上下文"里有开关，默认开。
- **只读的子智能体不再带文风工具**。Explore、Auditor、Reviewer 每次请求携带的工具从 21 个降到 13 个。
- **改章节不用整章重写**。助手可以只替换要改的那一段，输出量小很多，也更不容易被截断。

## 输出被截断时不再空转

以前默认最大输出是 4096，写一章正文很容易超过。超了之后工具参数是残缺的，助手会把同一个操作反复重发，白白消耗请求次数。

- 现在输出被截断且带着工具调用时，直接停下并提示调高输出上限，不会执行残缺的内容。
- 新添加的模型默认上限改为 8192。

## 修复：思考型模型报 reasoning_content 的 400

报错形如：

```
HTTP 400: The `reasoning_content` in the thinking mode must be passed back to the API.
```

DeepSeek 一类的思考型模型要求把上一轮的推理内容原样带回，旧版本把它丢掉了。现在流式和非流式都会保留并带回。只覆盖 OpenAI 兼容的 chat/completions 接口，Responses 接口未处理。

## 与上游对齐

- **流式接收回复**。回复改为边生成边接收，三种供应商协议和 OpenAI 的新旧两种接口都支持。超时改成"多久没收到新数据"，长章节只要还在生成就不会被掐断。个别中转站不支持流式或流式下工具调用异常时，在"设置 → 连接"关闭"流式接收回复"即可退回原来的方式。
- **助手可以管理卷**。新增 6 个工具：列出卷、新建卷、重命名卷、删除卷、删除章节、移动章节到其它卷。此前助手写新章节时可以指定卷，却没有办法知道有哪些卷。"设置 → 工具权限"里会多出这 6 项，写入类默认"每次询问"。删除卷或章节时，其中的笔记不会被删，会上浮到上一级。

上游还有联网搜索、网页读取、角色关系图谱、笔记分类、计划工具、技能管理和附件读取，这些会在后续测试版里陆续加入。

## 其它

- 检查更新能正确区分测试版和正式版，为后续测试版做准备。
- 如果以前手动改过"限流最多尝试次数"，它会保持原来填的值，不会变成 3。
