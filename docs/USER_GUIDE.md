# OpenFicM Android 使用说明

适用版本：0.7.7

OpenFicM 是本地优先的 Android 小说创作应用。安装后不需要电脑、FastAPI、Socket.IO 或其他自建后端；作品资料、章节、聊天记录、文风版本和本地索引默认保存在手机中。生成正文时仍需连接用户自行配置的模型供应商。

## 一、安装前准备

- Android 9.0 或更高版本。
- 64 位 ARM 手机（arm64-v8a）。
- 建议至少预留 500 MB 可用空间。
- 首次启动需要连接 GitHub 和 Hugging Face 下载运行资源。
- AI 生成需要用户自己的模型 API Key；OpenFicM 不提供公共模型额度。

从旧版升级时直接安装新版 APK 覆盖即可。不要为了升级先卸载应用，卸载会清除应用私有目录中的作品、对话、参考书和本地模型。重要作品建议先使用导出功能保存副本。

## 二、首次启动

首次进入会显示“准备 OpenFicM”页面，点击“一键拉取并预热”。应用会下载并校验：

1. OpenFicM 基础 Agent 和 Skill。
2. oh-story 写作 Skill 与移动端兼容子智能体。
3. Lorn 文风蒸馏资料。
4. 约 15 MB 的中文嵌入模型。
5. 约 209 MB 的中文重排模型。

所有资源都会保存到应用私有目录。模型下载完成后会校验文件大小和 SHA-256；Agent、Skill 和 Lorn 资料也会校验固定来源。远程脚本、Hook 和 Git 配置不会被执行。

若中途失败，可以在当前页面重试，或稍后前往“设置 → 高级 → 一键拉取缺失资源”继续。

## 三、配置模型供应商

进入“设置 → 模型与供应商”：

1. 选择供应商协议：OpenAI、Gemini 或 Anthropic。
2. 填写显示名称、Base URL 和 API Key。
3. 点击“保存供应商”。
4. 在已保存供应商右侧点击“获取模型”。中转站往往返回几百个模型，列表顶部有“查找模型”输入框，可按名称或模型 ID 过滤。
5. 在列表中选择模型，确认模型名称、模型 ID、温度和最大输出 Token 数。
6. 点击“添加模型”。
7. 点击模型左侧单选按钮，将其设为全局默认模型。

常用官方 Base URL：

| 协议 | Base URL |
| --- | --- |
| OpenAI-compatible | `https://api.openai.com/v1` |
| Google Gemini | `https://generativelanguage.googleapis.com/v1beta` |
| Anthropic | `https://api.anthropic.com/v1` |

第三方中转或自建兼容服务应填写服务商提供的 API 根地址，不要填写具体的 `/chat/completions` 或 `/messages` 请求地址。OpenAI-compatible 服务通常需要保留末尾的 `/v1`。

如果供应商不支持模型列表接口，也可以在“添加模型”区域手动填写模型名称和准确的模型 ID。

## 四、创建并管理作品

### 书架

- 点击书架右上角“+”创建作品。
- 点击作品进入写作页，同时将其设为当前作品。
- 点击作品右侧菜单或长按作品可以删除。
- 书架顶部可进入当前作品的角色库和世界书，也可进入全局文风库。

作品删除后，其卷、章节、角色、世界书、助手会话、文风关联和本地索引会一并删除，操作前会二次确认。

### 卷与章节

写作页顶部显示当前卷和章节：

- 点击目录按钮查看按卷分组的章节。
- 可新建、重命名或删除卷。
- 可在指定卷中新建、重命名或删除章节。
- 每部作品至少保留一卷。

打开章节时默认进入预览模式，避免触屏误改。点击“编辑”后才显示标题和正文输入框；保存后会返回预览。编辑期间支持自动保存、后台保存和输入法避让。

### 导出

写作页的导出入口支持：

- 当前章节导出为 Markdown。
- 当前卷导出为 Markdown。
- 整本小说导出为 Markdown。

角色库和世界书支持单条或批量导出为 JSON、Markdown。导出文件通过 Android 系统分享面板交给文件管理器或其他应用保存。

## 五、使用助手和 Agent

助手始终关联当前书架作品。切换作品后，只会加载该作品自己的对话，不会显示其他作品的聊天记录。

### 基本操作

1. 先从书架打开要创作的作品。
2. 进入“助手”。
3. 在顶部确认当前作品、主智能体和模型。
4. 按需切换当前会话使用的模型和创作文风。
5. 输入创作任务并发送。

助手不只是普通聊天窗口。Agent 可以按任务激活 Skill、调用本地工具、读取当前作品资料、委派子智能体，并更新章节、角色或世界书。执行过程会显示步骤、工具调用和结果。

建议直接描述目标和允许修改的范围，例如：

- “根据当前世界书和角色设定，规划下一章并写入新章节，写入前先向我确认。”
- “检查最近三章的角色动机和时间线，列出冲突后更新世界书。”
- “把这段创作思路整理成角色弧光和三章推进方案，不要直接写正文。”
- “使用当前文风重写本章对话，只修改正文，不改角色设定。”

### 工具权限

在“设置 → 工具权限”中，点击每项权限可循环切换：

- 允许：Agent 可直接执行。
- 每次询问：执行前弹窗确认。
- 禁止：Agent 不得执行。

如果 Agent 只回复建议却没有修改作品，先确认你的指令明确要求“写入、更新或创建”，再检查相应工具是否被禁止。

### 对话管理和失败恢复

- 顶部会话入口可新建、切换或删除对话。
- 每个会话可以单独选择模型。
- 用户历史发言可以编辑；编辑后，该条消息之后的旧分支会被删除并重新运行。
- API 或 Agent 执行失败时会保留任务，点击“重试”即可重新运行。
- 可展开“原始错误详情”检查 HTTP 状态、超时或供应商响应。

## 六、文风功能怎么用

OpenFicM 中有三种不同概念：

| 名称 | 用途 | 保存范围 |
| --- | --- | --- |
| 参考书 | 用户导入的小说原文，只作为蒸馏样本 | 全局文风书库 |
| 参考文风 | 从参考书提炼出的可执行写作约束 | 可跨作品使用 |
| 作者文风 | 从某部作品的 AI 原稿与作者定稿差异中学习 | 仅当前作品 |

“作者文风”菜单就是文风书库入口，不需要另填文风服务地址。蒸馏和进化都使用“设置 → 模型与供应商”中的当前默认模型，参考书详情页底部会直接显示当前是哪一个模型。

### 1. 导入参考书

从“书架 → 文风库”或“设置 → 作者文风”进入：

1. 点击导入参考书。
2. 选择 TXT、Markdown 或 EPUB 文件。
3. 点击已导入的书，可重命名、删除或开始蒸馏。

单个文件必须小于 50 MB，提取后的正文不超过 800 万字符。TXT 和 Markdown 支持 UTF-8、UTF-16、GB18030/GBK 等常见编码。请只导入自己拥有合法使用权的内容。

### 2. 蒸馏参考文风

选择参考书后点击“蒸馏文风”。应用会抽取全书开头的连续 24 章（无章节标题的书按每约 1,400 字符切段），分 4 批发送给你配置的默认模型分析，再汇总成一个参考文风版本。完整小说不会上传给模型供应商。

Agent 会根据 Lorn.NovelWriteSkills 方法分析句长、段落节奏、感官偏好、修辞指纹、禁忌词和去 AI 味规则，生成一个可查看、可删除、可重复迭代的参考文风版本。

**继续蒸馏**：一轮 24 章往往不足以代表一本长篇的文风。首轮完成后按钮会变成“继续蒸馏”，每点一次就向后随机跳到未读区域，再取一段连续 24 章，并把新证据并入现有指南，保存为下一个版本。例如 1,200 章的书，多轮走向大致是第 1-24 章、100-123 章、180-203 章、293-316 章……逐步铺满全书。

- 窗口只向后推进，不会重复已读区域，也不会跳过书尾。
- 面板会显示“已完成 N 轮蒸馏，覆盖到第 X/Y 章”。
- 每轮固定 5 次模型请求（4 批分析 + 1 次合并），中断后再次点击会从断点接着跑，不重复已完成的批次。
- 覆盖到书尾后“继续蒸馏”会停用，可点击“重新开始”清空进度、重新扫描全书。
- 换书或重新导入同名文件会使旧进度失效，自动从头开始。

### 3. 在创作中使用文风

- 写作页顶部可选择文风。
- 助手页顶部可为当前作品选择文风。
- 未选择文风而首次要求创作正文时，Agent 会询问是否选择。
- 参考文风可跨作品使用；作者文风只出现在其所属作品中。

选择后，文风约束会注入主智能体和正文类子智能体，而不是只在界面上显示名称。

### 4. 进化自己的作者文风

1. 让 Agent 创建或重写章节，应用会保存 AI 原稿和当时使用的文风。
2. 在写作页点击“编辑”，按自己的习惯修改正文并保存。
3. 返回预览后点击“进化作者文风”。
4. 模型会对比 AI 原稿和作者定稿，生成当前作品的新作者文风版本。

后续可以继续修改、继续进化。系统会保留多个版本，避免一次偶然改动直接覆盖长期写作习惯。如果当前章节没有可对应的 AI 原稿，或正文尚未产生有效修改，则不会提供进化入口。

## 七、角色、世界书与一致性

- 角色库用于保存人物外貌、性格、经历、关系和写作注意事项。
- 世界书用于保存地点、组织、时代背景、力量体系、时间线和其他规则。
- Agent 可通过工具读取和更新这些资料。
- 章节创作或修改后，Agent 可执行一致性检查，并根据实际剧情变化提出或写入角色、世界书更新。

建议把自动写入权限设为“每次询问”，既能保持协作效率，也能在重要设定变化前进行确认。

## 八、索引、规则、Skill 和智能体

### 本地索引

在“设置 → 索引”中可以启用语义索引和重排、调整分块与召回数量，并重建当前作品索引。嵌入和重排在手机本地运行，不会把整部作品发送给外部检索服务。

### 规则

“设置 → 规则”可添加长期约束，例如禁用某类表达、固定叙事视角或要求章节字数。启用的规则会进入 Agent 上下文。

### Skill

“设置 → 技能”可以启用或停用 OpenFicM、Lorn、oh-story 和自定义 Skill。Skill 会由 Agent 按任务需要激活，不需要用户每次手动选择。

### 智能体

“设置 → 智能体”可以：

- 选择当前主智能体。
- 启用或停用主智能体和子智能体。
- 为智能体指定模型或跟随全局模型。
- 创建自定义主智能体。

“设置 → 高级”可以检查应用自身的更新，也可以检查 oh-story GitHub Release、更新或回滚内容包。应用只导入白名单 Markdown，不执行上游 Hooks。

### 检查应用更新

“设置 → 高级 → 应用版本”会显示当前版本，点击“检查应用更新”会查询本项目 GitHub 上的最新 Release。有新版本时可点击按钮跳转到下载页，下载 APK 后直接覆盖安装即可，不需要卸载。这一步只读取公开的 Release 信息，不会上传任何本地数据。

## 九、数据与隐私边界

- 作品、章节、角色、世界书、对话、参考书和文风版本保存在手机应用私有目录。
- API Key 保存在 Android SecureStore，不以明文写入 SQLite。
- 调用模型时，会向所选供应商发送完成当前任务所需的提示词、对话和作品上下文。
- 文风蒸馏只发送当前轮次窗口内的章节样本，不发送完整参考书。
- 本地语义索引和重排不需要外部检索服务器。
- 卸载应用会删除本地数据；OpenFicM 当前没有云同步功能。

## 十、常见问题

### 一直停留在运行资源页面

检查 GitHub、raw.githubusercontent.com 和 Hugging Face 是否可访问，并保持足够存储空间。失败后可继续重试，已验证完成的资源不会重复安装。

### 获取不到模型列表

检查供应商协议、Base URL 和 API Key。部分兼容服务没有模型列表接口，可以手动添加准确的模型 ID。

### 助手请求超时或无法连接

在“设置 → 连接”调整超时时间，并检查网络、证书和 Base URL。失败消息中可展开原始错误后重试。

### 提示“模型在返回正文前就用完了 N 个输出 Token”

思考型模型（例如各家的 reasoning / thinking 版本）会把推理过程也算进最大输出 Token。如果这个上限太小，模型可能把预算全用在思考上，正文一个字都没返回。到“设置 → 模型与供应商”把该模型的最大输出 Token 数调大，或改用非思考型模型。文风蒸馏对输出长度要求较高，遇到这个提示的概率也更大。

### 换了模型后重试仍然报同样的错

0.7.6 之前，点击失败消息上的“重试”会沿用出错时记录的那个模型，换模型不生效，只能新建对话。0.7.6 起重试一律使用你当前选中的模型。

### Agent 没有写入章节或设定

明确要求 Agent 执行写入，并检查“设置 → 工具权限”中对应工具是否为“禁止”。设为“每次询问”时，需要在弹窗中允许。

### 没有出现“进化作者文风”

必须先由 Agent 工具生成或重写该章节，随后作者对正文作出实际修改并保存。普通手工新建章节没有 AI 原稿可供对比。

### 安装升级包提示签名冲突

只从项目 GitHub Releases 下载正式 APK。签名冲突通常表示手机上的安装包不是同一正式证书。卸载会清除本地数据，处理前先导出重要作品。

### 首次进入或重建索引较慢

嵌入和重排模型在手机 CPU 上运行，首次加载会比普通页面慢。旗舰手机可正常使用，但建议首次预热时保持应用在前台。

## 十一、推荐上手顺序

1. 完成首次运行资源下载。
2. 配置供应商并设置默认模型。
3. 新建作品，补充角色和世界书。
4. 在助手中先要求 Agent 制定创作计划。
5. 根据需要导入参考书并蒸馏参考文风。
6. 选择文风，让 Agent 创建章节。
7. 手动修改并进化作品自己的作者文风。
8. 定期导出整本小说和重要设定。
